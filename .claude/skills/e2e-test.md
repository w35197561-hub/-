# E2E 浏览器测试规范

通过 Playwright MCP 直接操控浏览器，验证新增组件在编辑器中的完整交互链路。

## 前置条件

确保开发服务器正在运行：
```bash
npm run dev:all   # 同时启动前端（5173）和后端（3000）
```

## 新增组件的验证流程

### Step 1：打开编辑器
导航到 `http://localhost:5173`，确认编辑器正常加载。

### Step 2：验证组件面板
在左侧组件面板中找到新增的组件类型，确认图标和名称显示正确。

### Step 3：拖入画布
将组件从面板拖入画布，验证：
- 组件在画布中正确渲染
- 组件可被选中（出现选中框）
- 位置和默认尺寸符合预期

### Step 4：验证属性面板
选中组件后，在右侧属性面板中：
- 确认 props 配置项正确显示
- 修改 props，验证画布中组件实时更新

### Step 5：验证撤销/重做
- 执行 Ctrl+Z，确认组件被移除（undo）
- 执行 Ctrl+Shift+Z，确认组件重新出现（redo）

### Step 6：验证图层面板
在图层面板中确认新组件的图层条目显示正确。

## 容器组件额外验证（Form / Tabs 类型）

- 将子组件拖入容器的 slot 区域，确认正确嵌套
- 验证容器内部状态切换（如 Tabs 切换标签页）不触发 undo 记录
- 确认子组件的选中、属性修改正常

## 交互型组件必须验证的渲染行为

对于有**排序、过滤、分页**等逻辑影响渲染内容的组件，E2E 必须额外验证：

- 触发交互后（如点击列头），实际渲染的数据是否按预期变化
- 不能只验证"点击没有报错"，必须断言 DOM 中的具体内容

示例（Table 排序）：
1. 进入预览态，找到 Table 组件
2. 点击"年龄"列头一次（升序），断言第一行年龄单元格内容为最小值
3. 再点一次（降序），断言第一行年龄单元格内容为最大值

> **背景**：composable 单测只验证逻辑层，模板层的取值错误（如用了错误的行索引）只有渲染测试才能发现。E2E 是验证"逻辑 + 模板正确配合"的唯一手段。

## E2E 是 reviewer 的强制步骤

reviewer 在审查完代码后**必须实际运行 E2E 测试**，不能以"单元测试通过"为由跳过。

运行命令：
```bash
npm run test:e2e
```

E2E 没有运行 = 审查未完成，不得执行提交。
